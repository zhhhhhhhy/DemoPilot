# 字段问答、共享能力与验收覆盖修复

本次只在开发资料上修复通用流程。正式最终题的原13/15成绩保留，剩余85条不运行。新协议不读取题号，也不根据问句里的中文关键词选择销售事实。

## 问答如何交接

意图模型每次追问同时返回自然语言问题、`field_ids`和`reason`。例如询问事先商定的单价，可以对应`pricing_rule.rate`；字段只能来自共享业务结构。服务器从同一对象生成网页里的问题文字，拒绝无字段、未知字段、同轮重复字段和文字列表不一致的输出。

网页仍由销售用自然语言回答。只有评测中的模拟销售使用`BusinessFacts`：按字段取预先声明的销售资料，返回值、可用状态与原始资料摘要哈希。交付过程不读取问句文字；重复追问重复交付同一原事实，没有“问过一次就不能再回答”的限制。冲突澄清保留原事实，不自动批准模型建议的新价格。该适配器不包含浏览器预期金额、操作路径或评分结果。

合法字段不等于模型语义一定正确：模型仍须把自然语言映射到正确字段，并整合多轮事实。开发实跑检查其最终草案是否逐值匹配销售事实；真实使用由销售确认完整规则后才进入Core。协议控制的1920个组合不能当作1920条独立需求或模型准确率。

## 两个模块用同一份说明

`quotation_capabilities.py`统一业务字段、10种计价结构、10种审批模板、日期与表单默认值、金额舍入和界面行为。意图提示与Core合同都由`render_capabilities()`生成，不再分别手工写两套说明。启动时检查能力列表和Pydantic业务结构一致；需要的业务事实与产品自带默认值明确分开。

每轮意图对话及Core输入保存相同版本/哈希的能力快照。确认时版本已经变化则要求重新核对，Core交接时再次核对标识；工作区中的测试输入不可改，原能力快照也在受保护文件列表中。此标识证明发送的能力定义相同，不证明模型必定遵从。

## 浏览器补查了什么

此前计算前会把参考表单值重新填进页面，可能掩盖记录切换后表单没有恢复的问题。现在在首次打开、切换记录、刷新之后，先读取真实输入值并与该记录已提交值比较，再继续后续操作。数字输入允许等价表达（如1与1.0）；暂未提交的编辑不与已提交值混淆。

对可点击但被业务规则拒绝的操作，直接检查`#error`可见且非空，并继续检查金额、状态、修订和历史没有错误改变。禁用按钮仍然是合法的拒绝方式。没有放宽原业务标准，也没有用生成代码的自我声明代替实际浏览器操作。

## 验证分层及可复现入口

1. 定向协议/API/浏览器断言回归：只覆盖本次改动路径，合计79项。
2. `scripts/check_business_field_protocol.py`：原32种手写问法搭配60组开发事实；同样问法比较旧关键词路由与新字段路由，并检查重复交付。已给定正确字段，不测试模型映射。
3. `scripts/verify_quotation_field_assertions.py`：同一真实CLI开发产物的正常副本、表单恢复破坏副本、错误提示破坏副本，对比旧/新检查。原产物不覆盖。
4. `scripts/verify_shared_contract_live.py`：预声明6条开发改写、2条部分回答多轮对话，以及价格冲突/不支持真实支付两个反例；4条开发需求继续真实Core生成，全部终态后才独立浏览器评分，不把独立最终结果反馈给Core改分。

模型保持gpt-6.1-sol、medium、每次300秒，正例最多3次意图和3次Core调用、并发最多2。先完成真实CLI读写和Chromium点击准备，调用、用量缺失、耗时、未通过和未运行分别保留。每次执行使用新目录，源码与输入固定；旧最终题计划因源码变化不能直接续跑，不能修改旧冻结清单来绕过限制。

## 实跑发现的额外工程遗漏

首轮开发验证的一次状态GET连接瞬断，被评测入口当成整个任务异常处理，继而取消了正在内部返工的Core。该次保留未交付，不把仍在迭代的Core判为最终能力失败。其余样例先按原冻结版本运行到终态，再修改查询机制，未在运行中热改源码。

修复只针对幂等状态读取：传输异常最多重试3次，沿用原整体截止时间；业务HTTP错误直接保留，创建、回答、确认、发布请求均不重发。原截止时间到达仍明确取消该任务。6项故障控制分别检查瞬断恢复、重试上限、业务错误不重试、原截止时间和同一任务持续观察。

单独复测沿用原开发题的改写、业务事实、模型、预算和标准，使用新目录。在实际Core开始后故意丢失一次状态读取，要求观察到重试、原任务继续完成，并通过独立浏览器检查。这个故障是明确注入的观察故障，生成和页面操作仍由真实CLI/Chromium执行。首轮7/8和单独复测分开报告，不合并冒充同批8/8；两批生产业务模块、意图提示、Core提示及浏览器检查源码完全相同，仅状态观察与评测选择/故障控制入口变化。
