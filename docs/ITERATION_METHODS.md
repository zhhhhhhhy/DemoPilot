# Engineering iterations

## IT-001: Move DemoPilot to an explicit intent -> acceptance -> result loop
- Date: 2026-10-05
- Status: implemented; live full-run follow-up remains bounded by model latency
- Problem and user impact: The current DemoPilot already freezes interaction contracts and records browser evidence, but its user-facing flow starts from a dense brief form and defaults to a remote provider. The article's most reusable idea—make the intent, the acceptance standard, and the result explicit—needs to be visible in the product. The local authenticated Codex CLI also needs to become a first-class iteration provider.
- Acceptance condition: A user can express boundary, priority, acceptance criteria, and constraints, confirm a one-page intent statement, choose Codex CLI, and submit. The run stores the intent statement, uses `codex exec --json` for agent calls, keeps the existing deterministic/browser/reviewer gates, and exposes result evidence and remaining human gates in the delivery view. Missing Codex auth or invalid structured output fails closed without silently switching providers.
- Proposed method: Add a bounded `codex_cli` provider around the local authenticated CLI; add backward-compatible intent fields and a deterministic intent statement; add confirmation and intent/acceptance/result cards to the Vue workflow; add unit, API, UI, and smoke checks.
- Work performed: Added `DemoRequest` intent dimensions and a durable `intent_statement`; added a fail-closed Codex CLI provider using `codex exec --ephemeral --sandbox read-only --json` with a strict schema wrapper, serialized local CLI calls, timeout/child-process cleanup, and no silent Mock fallback; added confirmation and intent/acceptance/result evidence cards to the Vue workflow; added API, provider, model, and UI regression tests; documented CLI configuration in `.env.example` and `README.md`.
- Observed result: Ruff passed; 47 backend tests passed; ESLint passed; 4 frontend tests passed; frontend production build passed; Mock API end-to-end delivery passed with intent fields persisted; Codex CLI 0.160.0 returned a non-empty structured Brief result using the saved ChatGPT login; a short-timeout process-cleanup check failed closed without orphaned CLI output. Full live Codex runs reached the real Agent Team but exceeded the 180-second per-agent guard during live service latency; a 600-second attempt reached the design stage before being stopped to avoid an unbounded account run, so browser/Reviewer evidence is not claimed for that provider run.
- Evidence: `docs/engineering/preflight-2026-10-05-02.json`, `docs/engineering/allocation-2026-10-05.json`, `docs/engineering/preflight-2026-10-05-03.json`, `backend/tests/test_codex_cli_provider.py`, `backend/tests/test_intent_statement.py`, `frontend/src/App.spec.ts`, and the final command outputs recorded in the task log.
- Remaining limitation or cause: No project `.env` or DeepSeek key is configured. Codex CLI authentication and Brief-level structured output are verified; a full nine-node live run remains sensitive to model-service latency and should be rerun with a deliberate higher timeout before treating its browser/Reviewer result as representative.
- Next method for this problem: Keep the deterministic Mock and local CLI smoke gates in CI, expose the configured timeout as an operator setting, and run one full Codex CLI acceptance task with a higher timeout when live model latency is acceptable.

## IT-002: Real Codex CLI debug, repair, and browser acceptance
- Date: 2026-10-05
- Status: completed; real Codex CLI and browser acceptance passed
- Problem and user impact: The previous run could prove only that the Agent Team started. It did not expose whether a slow call was still reasoning, whether the Windows CLI wrapper rejected a parameter, or whether a structured response failed before Runner. The user explicitly required a real end-to-end debug path and allowed assisted intent entry.
- Acceptance condition: Use the same browser-submitted synthetic intent and the `codex_cli` provider; preserve failed attempts; make every live CLI call observable without persisting model text; resume from checkpoints; require the existing approval, deterministic validation, Chromium interaction checks, and independent Reviewer before claiming completion. Mock must not be used as a fallback.
- Method: Add the DemoPilot-only `DEMOPILOT_CODEX_REASONING_EFFORT` setting (default `medium`), pass a bare `model_reasoning_effort=medium` CLI override so the Windows `.cmd` shim does not double-escape quotes, stream bounded JSONL metadata and 15-second heartbeats, retain safe call traces, and tolerate fenced/trailing text when extracting the structured agent object. Add a delivery-room debug trace and preserve the original timeout/parse/validation histories.
