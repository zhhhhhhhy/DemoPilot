## 修复了哪一层

修复的是运行监督和Core收尾，不改报价业务答案：启动/长停顿后零模型调用检查连接，恢复后只允许一次原预算真实调用，完成后才恢复并发；连续两次连接故障暂停后续调用，网页可见并可点“检查连接并继续”。运行中检测长时钟缺口并终止旧进程树，保留部分输出；原300秒及实际完成标记仍是硬门槛。

Core精简不必要的全局功能，显式保留已有Windows沙箱实现与workspace-write边界；只在继承的本地代理失效时使用已有可用Windows本地代理，限子进程生效。提示要求为收尾留出时间、完成全部必需检查后及时结束，没有增加模型调用次数或删验收。

旧记录缺少实际CLI结束标记，确属未收尾；旧091还花时间补测和写报告，第一次超时早于睡眠。历史路由故障已核实，但上游根因本轮没有稳定复现；不能宣称根治了官方服务/模型容量或所有超时。

## 先开发验证，再完整重跑

网页另注入两次受控连接故障：暂停时0CLI；真实点击恢复按钮，原会话继续，1次真实意图正确拒绝生产ERP/真实付款，0Core。这里故障刺激是受控的，网络、模型和浏览器操作真实，不能增加业务需求样本数。
