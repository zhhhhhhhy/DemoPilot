# 一次追问到底改变了什么

用保留题 quotation-05 说明。这题没有参与调试，页面由真实Codex CLI分别生成，再由本机Chromium实际操作。

销售最初只说：“帮我做一个客户优惠和批量优惠同时命中时能处理冲突的报价演示。”这没有告诉模型优惠数值，也没有说明哪个规则优先。

意图模块实际问了三个问题：客户优惠适用于谁、优惠多少；批量优惠的适用商品和数量门槛；同时命中时采用什么规则、能否叠加。

模拟销售在这些问题提出后才回答：A商品参与优惠，VIP优惠10%，数量至少5件时批量优惠20%；同时命中时VIP优先，只用10%，不叠加、不自动挑更大的20%。这个偏好由评测构造，公开文档支持“规则优先级”这种能力，不代表所有企业都应采用同一配置。

随后用相同输入操作两个最终页面：VIP购买6件A，原单价100元，目录小计600元。

|结果|优惠|应付总额|符合本题销售要求吗|
|---|---:|---:|---|
|明确要求|60|540|验收标准|
|直接生成|30|570|不符合|
|先询问后生成|60|540|符合|

直接组的数字反映了它自行选择的折扣规则，不能说它连600减30都不会算。问题是**它没有得到销售指定的规则，却交付了一个自己的版本**。询问模块的作用是补齐这些缺失事实，再完整交给同一个生成内核。

询问组这题12/12检查通过；直接组7/12通过。完整六条保留题仍按1/6对5/6报告，不能用这个成功例子代替全部结果。
