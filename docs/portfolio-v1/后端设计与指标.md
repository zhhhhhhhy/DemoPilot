# 后端设计与指标

## 当前能力

FastAPI 接收任务并返回运行标识；`RunManager` 将长任务交给 asyncio，避免一个 HTTP 请求承担完整生成过程。`RunStore` 在 run ID 下原子保存状态。SSE 按更新时间推送完整任务快照，重连可重取当前状态；它没有按 Last-Event-ID 增量重放事件。取消与恢复有单独 API，恢复是重新调度，并不等于 CLI 原生会话恢复或每一步恰好一次执行。当前调度器在单进程内运行，文件锁也是线程锁，不支持多个 worker 对同一记录做事务更新。

Core 与执行框架通过 `HarnessAdapter` 隔离，当前适配器是 Codex CLI。每个任务有独立工作目录；生成、内部检查和受信浏览器验收分别留下记录。通过后先复制候选，再从候选使用全新浏览器状态复核，最后修改发布状态。子智能体和模型最终文本都不能自行发布。

## 本轮实际修复

原实现只限制了等待子进程退出的时间，之后读取 stdout/stderr 的步骤没有同样的截止时间。测试复现了“外层进程已退出，但子进程仍持有输出管道”时的持续等待。原收尾函数调用 `communicate()`，也可能与已有的两个输出读取协程竞争。

修复将截止时间覆盖进程与输出读取的整个会话，让每个输出流只有一个读取者；超时和取消时终止受跟踪的进程树，允许有限时间排空输出，随后取消残留读取。意图评测的输出也改为随收到的数据增量保存，失败时仍能检查中途的 CLI 记录。

回归覆盖三个与用户可见行为直接相关的路径：真实子进程超时且已有输出保留、进程退出后仍不关闭输出、真实子进程被取消。没有通过缩短生成预算来声称修复成功。新的完整对照实验仍使用每个 CLI 会话 300 秒、最多 2 次 Core 返工。

本轮还修复了浏览器验收中的固定等待：原生选择框的显示标签和内部值不同时，旧代码先等待一个不存在的标签 5 秒才尝试值。现在先检查选项，保留标签优先的语义。相同真实浏览器样例从 5.192 秒到 0.547 秒，随后三页全部 24 条路径重放通过、原产物未改。这是控件路径的局部测量，不代表总生成延迟提升相同比例。

## 只读指标 API

`GET /api/runs/{run_id}/metrics`

| 字段 | 含义 |
|---|---|
| `status` / `publication_status` | 任务与发布状态，必须分开判断 |
| `persisted_elapsed_seconds` | 终态记录的创建到最后保存间隔；运行中返回 null |
| `recorded_agent_calls` | Core 记录的调用次数 |
| `core_iteration_count` / `core_revision_count` | 已记录迭代与返工次数 |
| `failed_core_acceptance_attempts` | 迭代中未通过检查的次数；不是最终失败数 |
| `observed_cli_session_count` | 保存了原始输出的 Core 会话数 |
| `observed_usage` / `sessions_with_usage` | 日志中 CLI 实际报告的 token 与具有报告的会话数 |
| `usage_complete` | 保存的 Core 会话是否都有 usage 记录；不等于完整账单 |
| `observed_failure_signals` | 观察到的连接、超时等信号；成功运行也可能出现重试警告 |

指标接口不读取或返回完整模型对话，不修改原运行数据。意图日志在实验目录，实验报告另外计入它的调用与 token。统计时只读取规范路径下每份会话日志一次；不存在的 usage 返回 null，不做零填充，也不将缓存 token 与输入 token 再次相加。

## 已核验的观测证据

`evidence/live-api-metrics.json` 来自本轮真实发布并通过完整业务复验的任务 `74f82dbc4215` 的 HTTP 请求，返回 2 次 Core CLI 调用、0 次返工与完整 usage；该任务的持久化时长约 239.996 秒。它是一个运行样例，不能代表总体生成耗时或线上 SLA。最初 API 观测另留在 `live-api-metrics-initial.json`。

历史证据收集器已经读到 41 个唯一 run，规范 Core 日志共 164 个会话，其中 136 个具有 usage。这 41 个是多项历史实验合并后的证据去重数，不是同一批评测的样本量，也不能拼成一个成功率分母。

加入本轮 6 个意图实验和 3 个业务回归 run 后，最终证据核验为 50/50 可读且发布状态无冲突。具体用量以 JSON 的每组字段为准。

## 下一阶段的后端取舍

真人销售问询需要独立会话 API 与前端回答、确认入口；这是当前实验 runner 接入产品的边界。多用户部署时，数据库条件更新、幂等键、任务租约与独立 worker、容器和资源限额应当一同设计。没有相应负载和隔离实测前，简历只写当前本地能力。
