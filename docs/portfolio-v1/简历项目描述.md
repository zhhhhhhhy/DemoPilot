# DemoPilot 简历项目描述

## 推荐使用

**DemoPilot｜面向售前场景的 Agent Demo 生成与验收系统**  
技术栈：Python、FastAPI、asyncio、Vue 3、TypeScript、Codex CLI、Playwright

- 围绕销售一句话生成可操作 Demo，设计意图询问、Core 迭代与结果展示三模块流程；通过可插拔 Harness 接入 Codex CLI，将目标、测试数据和验收方式组织成可执行任务。
- 实现运行目录管理、异步任务与状态持久化、取消恢复、SSE 状态同步和 CLI 过程留存；以子智能体静态探针、真实 Chromium 验收和候选复核控制发布，失败保持隐藏并回送 Core 修复。
- 基于公开报价规则构建10条需求，固定4条开发、6条保留并执行真实浏览器验收；比较原话、主动追问整理、完整规则直输三组，结果支持业务信息补全的价值，尚未证实意图整理带来额外最终通过收益（模拟销售、追加对照、单次小样本）。

最新数字、逐题结果和归因见[三组结果与简历贡献](../quotation-information-ablation-v1/结果与简历贡献.md)。六题的完整条件评分为原话1/6、询问整理5/6、完整规则直输5/6；功能操作检查为36/68、67/68、68/68。询问组一条操作超时、完整规则组一条读取检查误报均保留原分，不能写完整成功率100%。

若需要一句带效果的描述，可写：“实现主动获取并完整传递业务规则的实验链路，在6条模拟报价保留需求中，原话直接生成完整通过1/6，主动追问后5/6；追加完整规则直输对照后，未观察到意图整理的额外最终通过收益。”这说明信息获取流程的贡献，不能改写成意图处理算法独立提高准确率。

三组外层调用为14、25、18，Core内部返工为1、1、3；新增组3轮是在补齐验收执行证据，页面源码未改。没有节省返工、端到端人工工时或真实费用的结论；完整规则由实验者事先准备。

如果用于后端岗位，第一条可简化业务背景，在第二条后增加：“修复 CLI 子进程退出后管道未关闭导致的等待问题，为超时、取消和输出留存建立回归验证；新增只读运行指标接口，统计调用、返工、耗时及已报告 token。”

## 有篇幅解释时可加的实验结果

历史也有 5 个失败样本的定位与修复记录：2 个执行链路故障和 3 个产物问题，逐例复测 5/5 通过已知契约；另有 8 个多阶段案例通过已编写的契约。与新全量业务复验分开解释。

在 4 对相同案例的小样本 prompt 对照中，最终发布均为 4/4，结构化目标输入的 Core 返工由 5 轮降至 1 轮、CLI 调用由 18 次降至 10 次。需注明这是初步观察，且不是销售问询模块的实验结果。

20 例结果也可以写“基线 15/20，经失败样本修复后增量合并为 20/20”。优先使用推荐版的“失败复测 5/5”，避免简历读者误认为修复后做了单批全量 100% 验证。

## 本阶段不使用的表述

## 核验与归属说明

历史数字来自 `docs/portfolio-v1/evidence/portfolio-evidence.json`，可执行 `backend/.venv/Scripts/python.exe scripts/collect_portfolio_evidence.py` 重新计算。新报价专项使用[独立指标](../quotation-intent-v1/metrics.json)及其报告复算命令；两批不能混算。历史发布结果说明已知契约通过，不代表真实客户业务指标。

项目在参考代码与 AI 辅助实现基础上迭代；个人贡献集中在需求目标、架构取舍、后端可靠性、验收发布机制与评测决策。面试时如实说明开发方式，并准备解释关键代码。
