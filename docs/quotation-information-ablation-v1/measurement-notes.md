# 三组结果怎样理解

固定的完整评分保持A1/6、B5/6、C5/6。它同时要求交付、业务操作和读取边界检查通过；不能把它与单看页面功能的成绩混用。

页面实际操作检查是A36/68、B67/68、C68/68。新增C十题的112条指定功能检查全部执行并通过，其中六条主比较题68/68；四条调试题不混进主分母。

## C为什么功能全过，完整评分仍少一题

C06全部12条功能检查通过，但固定的文件读取检查把`../card-web/index.html`判成越界。查看完整6503字符命令后，唯一的`../`出现在写入`card/spec.md`的说明文字里，是网页入口链接；实际读取的是当前工作区的普通输入文件，写入也只在允许的卡片目录内。

这条命令没有读取私有答案，所示警告属于误报。原审计的标记和5/6成绩仍保留，没有改评分、重跑页面或重新生成；[原记录](../../evaluation_sets/quotation-intent-v1/results/full-rules-20261016/business-audit/quotation-06/full-rules/audit.json)及[机器可读分析](measurement-notes.json)可核对。

因此可以说六条C页面在指定功能操作中都做对了，不能把固定完整评分改写成6/6。B08同样保留原来的操作超时失败，诊断回放成功也不覆盖成绩。这两种观测问题均不能当作某种输入方法造成的业务能力下降。

## 三次内部重试是什么

C08两次、C09一次，原因是缺少可复核的验收子进程执行记录；Core在预算内自行补齐后完成。每题各轮页面源码哈希相同，不能把三次重试说成三次报价功能缺陷，也不能据此声称意图整理减少了业务错误。见[内部重试分类](core-retry-classification.json)。

## 哪些解释成立

五条原话不完整的主比较题，B和C拿到的销售规则文字完全相同。A有32条金额或赠品不符；B没有金额不符，但有一条操作超时；C没有金额不符和操作超时。这个结果支持：补齐业务事实后，同一个Core已经能够实现这些规则；本轮没有显示意图整理带来额外的最终通过收益。

自动询问的实际价值是让使用者不必一开始就写出完整需求。C的规则由实验者事先准备，没有统计人整理规则的时间，不能仅凭C少用几次模型调用就断言真实使用一定更省事。

本轮是后来追加C，沿用原六条保留题，并非新的未知题或同期随机试验；样本少、模拟销售、每组每题一次。人工整理需求的工时、真人销售满意度、客户转化等均未测量。原Core和评分源码保持不变，没有在这轮中修复守卫，否则会混用评分版本。
